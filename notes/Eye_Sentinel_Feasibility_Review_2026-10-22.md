# Eye Sentinel proposal 与 dataset 介绍检查

检查日期：2026-10-22。

本次以当前 Proposal v3 的五页正文、双语演讲备注、七页 dataset PDF、dataset Markdown、项目原始 brief、清理手册及 current 审计表为依据。未修改原 PPT/PDF，未重新训练模型，未重新逐图审查；统计结论复算自现有审计 CSV，不代表重新扫描全部原始文件。本次不复核历史 related-work 文献与 WHO 统计。

## 1. 必须采用的项目边界

- 只有四位组员，均无临床经验。
- 无法开展临床数据采集、临床实践、临床标签裁定或真实转诊试点。
- 工作以现有图像上的计算机视觉实验为主，使用来源提供的候选类别标签。
- 可以保留全球眼健康的动机，但项目交付应止于可复现的图像实验和离线演示。
- 临床合作不是本组承诺的下一阶段。若提及，只能作为实际应用所需、且本项目没有开展的外部条件。

结论：v3 第 2 页的图像基线方向可保留；第 1、3、4、5 页及对应演讲稿需要收缩。当前材料不是只多写了一句 future work，而是把主要叙事放在社区评估、症状融合、诊所协作和部署上，容易让评审按临床系统评价项目。

课程 brief 提供了“照片 + 问题 + 转诊”的产品愿景，同时明确写了工具由学生自行定义。这支持将本组范围限定为其中的图像研究部分，无需照搬整条临床产品路线。

## 3. 四人可以完成的技术范围

主问题可表述为：在现有、带噪声的眼部图像中，有限类别的分类基线表现如何，技术清理或图像来源变化会怎样影响结果？

最小交付建议：

1. 一个经过技术筛选的固定图像子集，以及来源标签到研究类别的明确映射。
2. 一个预训练 MobileNetV3-Small 分类基线。可比较冻结骨干与微调；不必展开大量架构搜索。
3. 一个核心比较：技术清理影响或来源变化影响，二选一作为主实验。
4. 固定留出测试集上的 macro F1、每类 precision/recall、混淆矩阵和支持样本数；accuracy 作为补充。
5. 展示现有图片和模型输出的离线 demo，以及可复现实验记录。

来源比较以两个集合有足够共同类别、相近拍摄类型且排除跨集合重复为前提；不满足时应报告不可做的原因，改用同一集合内的实验。不把它硬写成必须成功的 deliverable。

四人可分别负责数据清单与技术筛选、模型训练、划分与评估、demo 与结果整合；数据划分和标签映射至少由另一位组员交叉检查。无需设置临床联络、病例收集、问卷设计等角色。

类别先从 3–5 类的候选池筛选，实际数量以技术筛选后能否保留训练、验证、测试样本为准。数量不足时减少类别，不能靠增强图片补足独立测试样本。

EyeWorld 的 Wide-Field 目录可优先作为与原 brief 较接近的候选池；以下只是现存目录数量，不是已确认可训练的类别选择：

| 原目录标签 | 类别目录内图像数 |
|---|---:|
| Normal Eye | 515 |
| Strabismus | 179 |
| Pterygium | 153 |
| Hordeolum | 121 |
| Blepharitis | 99 |

这些类别仍可能混有不同设备、构图、临床表现或难以判断的标签。不要仅为凑足类别，强行建立互斥关系或宣称普通手机可以识别。若改做眼底任务，应相应改写研究背景和使用场景。

没有临床经验时，可做去重、文字线索处理、明显非照片过滤、格式和尺寸检查、分组与来源记录。不能把组员之间一致认为某病作为临床真值。22 张同图异标签样本继续排除即可，无需承诺由团队裁定。

## 4. Dataset 介绍：数量基本正确，但口径必须补齐

现有 `image_files.csv` 与 `class_counts.csv` 可复算为：

| 统计对象 | 图像数 | 正确解释 |
|---|---:|---|
| EyeWorld / Fundoscopy 类别目录 | 27,242 | 当前目录存量 |
| EyeWorld / Wide-Field 类别目录 | 4,886 | 当前目录存量 |
| FrontofEyeDx 类别目录 | 2,321 | 当前目录存量 |
| 上述类别目录合计 | 34,449 | 尚未完成最终建模筛选 |
| 单独复核区 | 22 | 同图异标签冲突，排除在类别目录之外 |
| 全部 source + review | 34,471 | 当前审计中的唯一 SHA-256 内容总量 |

因此 34,449 与 34,471 并不矛盾；当前介绍漏写了 22 张复核图。不能将 34,449 直接称为“已清洗可用训练图像”。

EyeWorld 原索引有 32,178 行，原始唯一图像内容有 32,150 个，当前类别目录有 32,128 张。索引行数、唯一内容数和类别目录存量应分开写。旧索引路径可能对应清理前位置，读取图片应使用当前清单或经过核对的路径映射。

已经核对正确的数字：

- FrontofEyeDx 有 94 个有图目录，共 2,321 张；每类 1–98 张，中位数 23；68 类少于 30 张。
- 数量分档为 14 类有 1–9 张、54 类有 10–29 张、23 类有 30–49 张、3 类有至少 50 张。
- 介绍所列六个眼底目录的数量均与当前类别表一致。
- 宽、高各自取中位数的口径正确；Wide-Field 原始中位数为 443.5 × 321.5 px，显示为 444 × 322 px 是合理取整，不代表某张实际图像的尺寸。
- 索引的 402 个 dx 值、397 个 label 值和 caption 示例次数与 metadata_summary 一致；这些是原索引统计，不是清理后类别数。

## 5. Dataset 介绍：需要实质修正的表述

| 位置 | 问题与证据 | 修正方向 |
|---|---|---|
| Markdown 开头、结尾路线表；PDF 第 6–7 页 | 明确提出采集手机照片、症状和临床参考标签，以及小规模试点 | 删除本组执行这些阶段的承诺，改为现有图像实验、评估与离线展示 |
| Markdown 来源表；PDF 第 2–3 页 | 将全部 FrontofEyeDx 称为眼前节近照。实际目录有 Diabetic retinopathy 33 张、Retinal detachment 17 张、Glaucomatous optic neuropathy 32 张、Vitreoretinal traction 41 张等 | 改称按疾病名称组织的异质眼部图像集合；图像模态需逐图或抽样核对。目录名称本身也不能证明每张图的拍摄模态 |
| Wide-Field 描述 | 容易让读者将目录名理解为统一拍摄方式或普通手机照片 | 说明是包内目录名，包含不同子集合；不能据此推定设备、拍摄条件或手机适用性 |
| “合并同义写法后” | 402/397 个字符串值不证明差异全是同义词；标签可能处于疾病、病因、部位等不同层级 | 区分机械字符串标准化和需要专业知识的疾病合并；仅做可解释、有记录的映射，不自行临床裁定 |
| “模型训练时只输入照片像素” | 这只能排除文本字段作为输入，像素里仍可能有疾病文字、箭头、边框和拼图线索 | 增加图内泄漏检查；难以安全处理的图可以排除，并保留处理记录 |
| PDF 第 5 页“新病例” | 对 ODIR 按 orig_id 分组合理，但其余集合没有完整病例 ID，近重复也未被完整排除 | 仅对有证据的子集声称按 ID 分组；其他部分写图像/相关图像簇隔离，说明病例身份不完整 |
| “独立评估” | 同一个混合图像包里的留出测试不自动等于独立来源或外部临床验证 | 用“固定留出测试”；若另做来源留出，交代具体来源与可覆盖类别 |
| 每类“灵敏度” | 在当前数据上是相对于来源标签的类别 recall，读者可能误解为临床漏诊率 | 优先称每类召回率，并写明标签和测试集范围；macro F1 应解释为各类别 F1 的算术平均 |

ODIR 的 7,000 张图、3,500 个 orig_id 及左右眼配对统计正确。但如果最终只研究外眼/眼表子集，ODIR 不参与主模型，可移到数据附录；不能把该子集的人口学字段推广到全数据集。若使用 ODIR 的多标签信息，应先确认标签的记录单位与语义，不能直接把它当作互斥的单眼类别。

FrontofEyeDx 各类通常样本很少，例如 Pterygium 只有 25 张。即便拿出 5 张测试，错 1 张就会使该类召回率变化 20 个百分点。不要只展示百分数或承诺稳定的跨来源结论，必须同时报告分母。

## 6. 实验设计的最低边界

- 技术清理、去重簇及相关图像分组应在划分前安排；训练、验证和测试不能共享同图、裁切版本或同一拼图衍生图片。
- SHA-256 只排除字节完全相同的文件；当前“0 重复”不表示没有近重复或同病例。
- 固定测试集，增强仅用于训练。类别选择、阈值和超参数依赖训练/验证数据，不用最终测试分数反复选方案。
- 清理比较应使用相同的测试目标与分组约束。不能让“未清理组”跨划分泄漏，然后把虚高分数当成正常基线。
- 合成模糊、曝光、压缩实验可作为选做项，但不称为真实手机场景验证。
- softmax 分数不直接等于正确概率；没有专门评价时，不把低分提示包装为可靠的临床拒识或质量控制。
- 不要求检测框、分割、多模态融合、疾病严重程度或转诊预测；现有目录级标签不足以支持这些额外任务。

## 7. 建议统一使用的范围表述

> 本项目由四名无临床背景的学生完成，使用课程提供的现有眼部图像，研究少数来源标签类别的图像分类。我们将进行技术数据清理、训练轻量迁移学习基线，并在固定留出数据上分析分类结果和错误。项目不开展新临床数据采集、临床标签裁定或真实医疗流程试点。最终交付为可复现实验、数据限制说明和离线演示。

Global health 的联系可写为：理解低成本眼部图像模型在噪声数据、有限样本及来源差异下的能力与局限，为后续独立研究提供技术依据。现有实验无法证明临床筛查效果、实际转诊收益或普通手机场景的可靠性。
